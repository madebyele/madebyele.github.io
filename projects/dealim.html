01 · Overview

한 번의 구축보다
지속적인 운영을 고려한 작업

서로 다른 구조를 가진 복수 사이트에서 들어오는 요청을 확인하고, 기존 서비스에 미치는 영향을 살핀 뒤 퍼블리싱 작업을 진행했습니다.

업무 범위는 신규 페이지 제작, 기존 페이지 리뉴얼, 운영 UI 수정, 반응형 보완과 브라우저별 표시 문제 대응이었습니다. 새로운 화면을 만드는 것뿐 아니라 이미 운영 중인 화면을 안전하게 변경하는 과정이 중요한 프로젝트였습니다.

Operation Scope
약 6–7개 계열사·브랜드 사이트
Work Type
신규 제작 · 리뉴얼 · 운영 수정
Quality
반응형 · 크로스브라우징 확인

02 · Context / Problem

운영 환경에서 마주한 과제

  1. 01

    서로 다른 기존 구조

    사이트마다 마크업과 스타일 구조가 달라 요청 내용을 반영하기 전에 기존 구현과 영향 범위를 먼저 확인해야 했습니다.

  2. 02

    요청 단위의 다양한 작업

    신규 페이지, 리뉴얼, UI 수정과 유지보수 요청이 함께 들어오는 환경에서 작업 목적과 우선순위를 구분해야 했습니다.

  3. 03

    반응형·브라우저 차이

    특정 화면 크기나 브라우저에서만 나타나는 문제를 재현하고, 다른 화면에 영향을 주지 않도록 수정해야 했습니다.

03 · My Role

담당 범위와
협업 범위의 구분

My Responsibility

퍼블리싱 전담

  • 요청 화면의 기존 마크업과 스타일 구조 확인
  • 신규 페이지 제작 및 페이지 리뉴얼 퍼블리싱
  • 운영 UI 수정과 JavaScript/jQuery 인터랙션 대응
  • 반응형 화면과 브라우저별 표시 상태 확인
  • Git 기반 소스 관리와 Jira 이슈 단위 협업

Collaboration

디자인·개발 담당자와 협업

디자인 산출물과 요청 내용을 기준으로 화면을 구현하고, 개발 연동이 필요한 영역은 담당 개발자와 확인하며 작업했습니다.

이 Case Study는 본인이 담당한 퍼블리싱 업무만 기술하며, 기획·디자인·개발 전체 결과를 개인 성과로 표현하지 않습니다.

04 · Approach

요청을 화면에 반영하는 과정

  1. 01

    요청 확인

    Jira와 협업 내용을 통해 작업 목적, 대상 페이지와 필요한 변경 범위를 확인합니다.

  2. 02

    현행 구조 분석

    기존 마크업, 스타일과 UI 동작을 살펴 수정 영향 범위를 파악합니다.

  3. 03

    퍼블리싱 구현

    기존 구조와 운영 조건을 고려해 페이지 또는 UI 변경 사항을 구현합니다.

  4. 04

    화면 검수

    Desktop과 Mobile, 주요 브라우저 환경에서 표시 상태와 인터랙션을 확인합니다.

  5. 05

    공유 및 반영

    Git으로 변경 사항을 관리하고 필요한 수정 내용을 Jira를 통해 공유합니다.

  • 계열사 및 브랜드 사이트의 신규 페이지와 리뉴얼 화면 구현
  • 운영 과정에서 발생한 UI 수정과 반응형·브라우저 표시 문제 대응
  • Git과 Jira를 활용한 변경 사항 관리 및 협업
