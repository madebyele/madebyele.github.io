01 · Overview

한 번의 구축보다
지속적인 운영을 고려한 작업

서로 다른 구조를 가진 복수 사이트에서 들어오는 요청을 확인하고, 기존 서비스에 미치는 영향을 살핀 뒤 퍼블리싱 작업을 진행했습니다.

업무 비중은 운영 페이지 유지보수 약 50%, 신규 페이지 제작 약 25%, UI 개선 약 25%였습니다. iOS에서 발생한 CSS 표시 문제에 대응하고, 분양 사이트의 표 데이터 계산을 JavaScript로 자동화하는 작업도 진행했습니다.

02 · Context / Problem

운영 환경에서 마주한 과제

  1. 01

    서로 다른 기존 구조

    사이트마다 마크업과 스타일 구조가 달라 요청 내용을 반영하기 전에 기존 구현과 영향 범위를 먼저 확인해야 했습니다.

  2. 02

    요청 단위의 다양한 작업

    기획자로부터 Teams나 Outlook으로 작업 요청을 받은 뒤, 긴급도와 중요도를 기준으로 작업 우선순위를 정했습니다.

  3. 03

    반응형·브라우저 차이

    iOS에서 CSS 표시가 깨지는 문제에 대응해야 했습니다. 분양 사이트에서는 표의 수량과 금액을 합산하거나 사칙연산한 결과를 수동으로 계산·입력하는 작업도 줄이고자 했습니다.

03 · My Role

담당 범위와
협업 범위의 구분

My Responsibility

퍼블리싱 전담

  • 요청 화면의 기존 마크업과 스타일 구조 확인
  • 신규 페이지 제작 및 페이지 리뉴얼 퍼블리싱
  • 운영 UI 수정과 JavaScript/jQuery 인터랙션 대응
  • 반응형 화면과 브라우저별 표시 상태 확인
  • 분양 표의 수량·금액 합산 및 사칙연산 결과를 JavaScript로 자동 계산

Collaboration

기획자와 요청·검수 협업

기획자가 Teams나 Outlook으로 전달한 요청을 확인하고 긴급도와 중요도에 따라 구현·검증했습니다. 이후 기획자의 최종 검수를 거쳐 작업을 완료했습니다.

이 Case Study는 본인이 담당한 퍼블리싱 업무만 기술하며, 기획·디자인·개발 전체 결과를 개인 성과로 표현하지 않습니다.

04 · Approach

요청을 화면에 반영하는 과정

  1. 01

    요청 확인과 우선순위 정리

    기획자로부터 Teams나 Outlook으로 작업 요청을 받고, 대상 페이지와 변경 내용을 확인한 뒤 긴급도와 중요도를 기준으로 우선순위를 정했습니다.

  2. 02

    현행 구조 분석

    기존 마크업, 스타일과 UI 동작을 살펴 수정 영향 범위를 파악했습니다. 요청에 따라 운영 페이지 유지보수, 신규 페이지 제작과 UI 개선을 진행했습니다.

  3. 03

    실무 사례 · iOS CSS 호환성 대응

    iOS에서 CSS 표시가 깨지는 문제에 대해 Can I Use로 해당 CSS의 브라우저 지원 범위를 확인했습니다. 지원 여부에 따라 CSS를 수정하거나 해당 속성 사용을 지양한 뒤, iOS 실기기에서 표시 상태를 검증했습니다.

  4. 04

    실무 사례 · 분양 표 데이터 자동 계산

    분양 사이트의 표에서 수량과 금액을 셀별로 합산하거나 데이터에 필요한 사칙연산 결과를 JavaScript로 자동 계산하도록 구현했습니다. 계산 결과를 직접 입력하지 않아도 되도록 하여 수동 계산·입력 작업을 줄였습니다.

  5. 05

    구현 검증과 기획자 최종 검수

    구현 후 화면과 동작을 검증하고, 기획자의 최종 검수를 거쳐 작업을 완료했습니다. 작업 요청과 협업은 Teams와 Outlook을 중심으로 진행했습니다.
